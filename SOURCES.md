# Corresponding Source

The included browser application is based on Joplin Mobile/Web **3.7.0**, built from upstream revision **425a05ac4b03ab84e038f67a6bcc029377d1b50e**, on the upstream `release-3.7` branch. This identity was verified using the running application's version information. The application bundle has one source-anchored addition to its note-list render method; worker bundles remain unchanged. Original and resulting asset hashes, including local UI assets, are recorded in `upstream-assets.json`.

To rebuild the UI from corresponding source, check out the exact upstream revision, enable Corepack, run `yarn install` at the upstream repository root, then run `yarn web` from `packages/app-mobile`. Its output is `packages/app-mobile/web/dist`. Upstream package dependencies and build tools are needed for this source build; this small deployment repository intentionally does not duplicate unrelated upstream native and desktop projects.

This repository contains the source for the Node.js static host and fixed-backend API proxy, extraction/adaptation tools, card-view UI, tests, and Docker configuration. The adaptations replace document titles and manifest icons, disable development mode, identify the web process stub explicitly, and add local note cards with a compact-list toggle. `web/note-cards.js` loads excerpts through Joplin's original note model and reuses its Markdown parser and note-item actions. No separate credential storage or sync engine is introduced.

To reproduce the distribution, run `npm ci`, then `node tools/extract-web.mjs`. Extraction automatically runs `tools/customize-note-list.mjs`; run that tool directly after editing the local card script or stylesheet to refresh their recorded hashes. It parses the compiled bundle, validates the pinned note-list/model/icon/Markdown module anchors, adds the one render bridge, updates the HTML/bootstrap, and records resulting hashes. It deliberately fails if the upstream modules change instead of silently patching an unknown build. The regression test removes the bridge and verifies that the original application's source hash is restored. After refreshing to another upstream release, review these anchors and update this document to match the newly generated provenance file.
